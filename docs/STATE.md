## Built
1. **Console voice.** Organizer and host screens say "you". Zero first-person strings, kept by `apps/web/test/console-voice.test.ts`. Left as is on purpose: the agreement boxes (legal), the partner pages, the AI assistant's own sentences.
2. **Start wording.** "The game starts by itself" and "Numbers come by themselves / A new random number appears every 12 seconds." (new games start at 12 seconds). The other two formats are **coming in 1.6.0** (below).
3. **Invite people with just an ID.** One ID box; every non-letter and non-number dropped, then capitals (`A-1101` = `A 1101` = `A/1101`) at upload, join, approval and matching. The owner's five lines are on the console screens. Paste a list, PDF or CSV. Listed IDs join with no approval; unlisted IDs wait for a yes or no. Family invite is **1 to 4** per listed person (live's owner decision of 1 Nov 2026; the 1 to 10 of the first draft was changed back when the live code was merged). Invite log for the organizer and hosts only. Old stored IDs still match (`legacyEmpFor`). The waiting room is capped per network (1.5.3: 100 requests in 30 minutes; an IPv6 /64 is one network); there is no wrong-ID limit any more.
4. **The server refuses an open game (1.5.0, audit finding 3).** A create or a save that says `whoCanJoin: "anyone"` (or `closed: false`) is refused with code `list-only`; a game that says nothing is a game for the people on its list. `LEGACY_OPEN_GAMES=1` is the old behaviour; only the old tests set it (`apps/edge/test/with-terms.ts`); never set it on the live site. Tests: `apps/edge/test/audit-1-5-1.test.ts`. Games that are already open stay open after a save that leaves out both `whoCanJoin` and `closed`; they close when a save says `whoCanJoin: "list"` or `closed: true`. (1.5.1, audit of 23 Nov, Medium 1: on a save, `closed` is accepted only when absent or `true`; `false`, `0`, `null` and `""` are refused too. Before, `null` and `""` re-opened a closed game.)
5. **Paid only through the console.** `POST /api/console/paid`: the console's signed notice, once per order id, forged/replayed/wrong-game/wrong-size refused, a stuck order is released after 30 seconds and can safely run twice. The game starts only when paid. The bridge is a byte-for-byte copy of corporate-console `2db8168` (`apps/edge/src/console-bridge/`, hash test `bridge-copy.test.ts`).
6. **`payInfo` (1.5.0, audit finding 2).** `POST /api/console/payinfo { assertion, eid }` answers, before any money is taken: the pack size to charge as a string (`item`, the same value the paid notice later checks), whether the game can be paid (`payable`), whether it already is (`paid`), and a reason (`already_paid`, `closed`, `too_big`). Never a price. Only the owner of the game gets an answer; anybody else gets the same "not found" as for a game that is not there. Signed and used once, like the paid notice; dark without `CONSOLE_PUBKEYS`; changes nothing. **The console's contract (`PAY_STEP.md`, bridge v1) has no such call**, so the console has to adopt this one; because the copied bridge has a closed list of purposes, the assertion uses the purpose `games`. Tests: `audit-1-5-1.test.ts`. (1.5.1: the body is read with a 4096-byte limit, 413 above it; a network that sends 20 requests in a minute that cannot be checked gets 429 for the rest of that minute; the count is kept in memory, no database write.)
7. **Flags (both OFF).** `PAY_VIA_CONSOLE=1` closes this game's old pay pages and routes (Razorpay's own notice is never turned away). `LOGIN_VIA_CONSOLE=1` sends the game's own sign-in to home. **The name of the pay flag in this game is `PAY_VIA_CONSOLE`.** `PAY_VIA_MONEYPENNY` is the console repository's own flag; it does nothing here. Set `PUBLIC_ORIGIN` and `CONSOLE_PUBKEYS` first.
8. **Deleted within 24 hours.** The list, requests, seats, ID look-ups, waiting-room counters and log go with the players' data 20 hours after the game ends. No page promises a PDF by e-mail (the report e-mail carries a link).
9. **Other owner wording.** Rupee sign, the privacy line "designed to follow US privacy laws, the EU GDPR and India's DPDP", the fairness sentence (proved in code by `packages/beacon/test/fairness.test.ts`), no forbidden claims (`owner-text.test.ts`), billing line exact.
